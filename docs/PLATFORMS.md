# 四端交付与真实集成边界

## 已实现的共用功能

购物返积分商城：首页商品推荐、商品详情、分类搜索排序、收藏、购物车、收货地址、优惠券、结算与订单状态流转。测试付款→商家登记发货→确认收货，才发放购物积分。积分可兑换购物券，在下一笔满足条件的订单结算中抵扣；退款需回收已发购物积分。签到和广告仅作为补充。运营界面保留广告位和风控管理，增加购物订单查看。

真实商品交易、真实广告、微信身份认证、数美 SDK、支付、物流、推送、账号注销、后台多角色登录尚未实现。当前不是商用完成版。

## 构建与发布

| 端 | 命令与输出 | 仍需完成 |
| --- | --- | --- |
| H5 | `npm run build` → `dist/build/h5` | HTTPS 托管、同域 `/api` 反向代理、备案及正式认证 |
| 微信小程序 | `npm run build:weixin` → `dist/build/mp-weixin` | 自有 AppID、合法域名、微信开发者工具验收、真机测试、隐私配置、平台审核 |
| Android | `npm run build:app` → `dist/build/app` | HBuilderX / 原生打包环境、应用标识、签名、SDK 集成、真机测试及商店审核 |
| iOS | 同上，生成共用 App 资源 | macOS/Xcode 或合规云打包、Apple 开发者账号、证书及描述文件、ATT/隐私清单、真机测试与审核 |

`dist/build/app` 是资源包，不是 APK、AAB 或 IPA。本环境的编译成功不证明四端真机运行正常。不得将空 AppID 当成已配置。

设置设备环境可访问的 `VITE_API_BASE=https://api.your-domain.example/api` 后重新构建。设备不能使用开发机器的 127.0.0.1。正式版必须使用可信 HTTPS；小程序必须登记合法域名。不得关闭域名校验或 TLS 验证。

## 广告

五个可运营管理的位置：首页、商城信息流、任务激励、商品详情、会员页。默认关闭占位预览，后台可开启。占位预览不加载广告、不统计曝光或收益。任务页独立的 8 秒内部演示仅用于验收交互，不能被用于真实广告结算。

- App：需依据穿山甲当前支持范围、应用类别及审核结果选择 Android/iOS SDK 或官方认可的 uni-app 接入方案。不得在未同意隐私条款前初始化会采集数据的 SDK。
- 微信小程序：使用微信当前支持并批准的广告能力，不能直接运行穿山甲原生 App SDK。不能承诺穿山甲覆盖四端。
- H5：需单独确认服务商是否提供适用该业务的广告产品；不得用定时器模拟真实观看凭证。
- 激励链路：服务端创建一次性任务 → 平台完成凭证/经文档确认的服务端回调 → 验签、防重放、核对用户与广告位 → 风控 → 原子发积分。客户端 `onClose` 或一个播放计时器不能成为正式发奖凭据。
- 关闭回调、库存、并发、重放、退款联动、结算对账均需真实沙箱验证。

当前没有广告应用 ID、广告位 ID、平台回调验签配置或真实 SDK。正式模式会拒绝启动，避免误用演示链路。SDK 选择、审核和收费需要运营主体提供真实资料，不得伪造。

## 第三方风控

目前只实现本地限频、领奖上限、重复领奖拦截、跨账户隔离、账户限制与审计，未连接数美。真实接入需要：组织与应用信息、已批准的数据采集 SDK、服务端访问绑定、经过官方文档确认的接口与签名协议、用户同意记录、超时降级及人工复核流程。秘钥只能放在受控服务端，不能放入 `VITE_*` 或客户端。

数美未配置时，不向第三方发送设备、IP 或账户数据，也不伪造“已通过数美认证”。高风险奖励应先冻结待审，第三方不可用时不能直接允许高价值兑换。

## 合规设计边界

积分不直接售卖、不提现、不转让；只做确定性兑换。没有付费抽奖、现金收益承诺或朋友圈分享奖励。积分任务与广告奖励仍需符合具体平台现行规则；这不是自动获得法律许可。

正式运营还需完成主体信息、用户协议、完整隐私政策、第三方 SDK 清单、权限申请、注销及数据权利通道、客服申诉、商品履约、发票售后和消费者权益流程，并按运营地区评估资质与规则。

## 测试购物账务

- 实付金额使用整数分，商品金额、优惠门槛、库存和奖励均由服务端计算，禁止提交任意价格或奖励。
- 优惠后金额每满 100 分奖励 1 积分，确认收货后发放；付款不直接发放。
- 下单预占库存和优惠券；取消或测试退款后仅恢复一次。
- 订单幂等键绑定商品、数量、地址和优惠券；更换参数时不能复用同一键。
- 已使用返积分而导致退款扣回不足时，返回人工审核提示，订单和积分保持原状。已提供售后审批工作台；余额不足时的账务差异处理仍需后续流程，不得强行批准。
- `demo-pay`、`demo-ship`、测试退款是测试环境专用接口。并无真实支付和物流，不能把用户点击当作第三方支付通知，也不能用于正式运营。
- 地址仅供测试，请勿填写真实个人信息；正式环境仍需 PII 加密、权限和脱敏策略。

## 0.3.0 受控试用交付

增加独立商家商品/库存管理、发货记录、售后申请与审批、积分倍率设置，用户端移除自行发货和直接退款按钮。旧测试接口仅在服务端 demo 模式保留向后兼容，不代表具备真实支付和物流能力。

`delivery/aurora-0.5.0-server.zip` 包含预构建 H5 和仅 API 依赖的运行包。`npm start` 提供同源网页和 API，不依赖 Vite 开发服务器。仍须用 HTTPS 与访问范围限制保护，不可视为正式公开运营。运行包依赖和源码构建依赖分别审计；审计无报告不等于安全认证。

## 0.5 受控账号与积分兑换履约记录

账号密码注册和登录可恢复同一账号，改密会撤销已有会话；保留匿名体验但不自动合并两种账户。尚无短信、邮箱或微信身份验证、密码找回与完整生产账号治理。

实物积分兑换现在有商家处理说明和客户记录页，说明属于测试人工登记，不是实际物流通知。数据库增加可验证的独立恢复工具，恢复成功后仍需停服、备份、切换配置及业务验收。
