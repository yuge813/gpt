# 安全状态与上线门槛

这是受控环境的功能演示与开发基础，不是完成安全认证的商用品。“大厂级安全”必须由威胁建模、独立审计、渗透测试、真实运行监测和组织流程证明。

## 已实现

- 服务端计算积分；使用事务把库存、积分流水、订单一并提交，失败回滚。
- 兑换幂等键按用户隔离；重复请求不重复扣分；账本事件唯一。
- 演示广告会话一次使用，归属校验、最短时长、有效期、每日上限、冷却和重放拒绝。仅为演示，不可复用于真实广告验收。
- 32 字节随机会话凭证、服务端 SHA-256 存储、七天到期、退出撤销。
- 参数 JSON Schema 严格校验，禁止附加字段和类型强转；SQL 参数绑定。
- 16KB 请求上限、请求限频、安全响应头、私有响应不缓存、明确 CORS 允许来源。
- 管理接口独立校验至少 32 字符凭证，定时安全比较；无默认后台密码；管理员凭证不持久化到前端存储。
- 广告开关、广告位置开关和人工限制均有数据库审计；受限账户不得签到、领奖或兑换。
- 正式模式未接入时拒绝启动。开发服务绑定回环地址。

## 不应误解的边界

演示注册不是生产级身份认证，重新注册可获得新的演示积分。浏览器本地保存会话凭证，未实现 HttpOnly Cookie / BFF、MFA、RBAC、会话设备管理或真正的反女巫能力。单进程内存限流不能替代分布式限流。数据库是本地 SQLite，未提供多机高可用、异地灾备和生产加密密钥管理。

当前积分流水、审计是普通数据库表；不能声称不可篡改。风控记录中的人工限制不是数美服务。账户注销、数据保留删除策略、申诉后台、真实广告验签、支付与退款账务尚未完成。

## 依赖与工具链

依赖使用锁文件，TLS / npm 完整性验证保持开启。为修复上游漏洞，显式覆盖部分构建依赖版本，并使用 Vite 6.4.5；该版本超出 uni-app 插件原始 peer pin，需要持续跨端回归。Vue 编译器与 uni-app 定制运行时保留兼容的 3.4.21 组合，不能只因版本新就替换编译器。

最近一次依赖审计返回 21 个 high 告警（包含依赖链传播），直接来源是构建工具链中的 `braces` 深层嵌套模式栈耗尽问题；没有可用的已发布修复版本，尚未关闭。服务端业务不会接收或解析 glob 模式，但仍需完成独立适用性评估。完整报告见 `docs/dependency-audit.json`。

仓库的 `docs/validation.json` 保存最近一次完整验证的结果及审计摘要。依赖审计不等于漏洞可利用性评估；有遗留告警时禁止宣称“零漏洞”。`braces` 构建依赖若无修复版本，必须继续跟踪上游；仅编译可信仓库，开发服务器不得直接向公网开放。

1. 微信/App/H5 真实认证、后台多角色与 MFA、会话保护、验证码/注册风控及账户注销。
2. PostgreSQL 等生产数据服务评估、迁移与备份恢复演练、持久化分布式限流和任务队列、密钥托管、最小权限与审计留存。
3. 广告平台真实验签与结算验证、数美真实沙箱验证、隐私同意与撤回、权限和 SDK 合规测试。
4. 支付签名、退款与库存补偿、履约售后，及真实商品/权益授权。
5. CI 安全门禁、依赖与镜像扫描、独立渗透测试、真机测试、压测与故障演练、监控告警、值班响应和回滚。

不得把当前演示直接作为公网积分兑换或广告变现服务。
