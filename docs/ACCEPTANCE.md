# 当日交付验收清单

交付目标：能本地运行、能在宝塔受控部署的购物返积分测试商城。客户操作、运营后台和账务规则真实落库；测试付款不产生真实扣款，发货是商家手工登记，不冒充物流平台。通过本清单不代表已完成商业上线或四端商店审核。

实际运行次数、通过/失败/跳过项目以 `docs/validation.json` 和执行输出为准。下面是验收标准，不是自动宣称全部已经通过。

## 购物、积分与优惠券

| 场景 | 验收结果 |
| --- | --- |
| 账号密码 | 注册初始0积分，退出后可用账号重新登录；密码不明文存储，改密撤销旧会话，旧密码失败 |
| 新账户 | 明确同意体验说明后创建；可用积分从 0 开始，不伪造购物收入 |
| 商品搜索、分类、排序、详情 | 搜索能出现匹配项/空结果；价格与返积分可见；图片加载失败不能当作完成 |
| 购物车 | 数量更新、移除、总价正确；不能购买负数、越库存数量或仅供积分兑换的商品 |
| 收货地址 | 新增、选择、删除按账户隔离；只使用虚构数据 |
| 结算 | 服务端计算价格、优惠门槛、实付金额和返积分；客户端注入价格或奖励被拒绝 |
| 重复提交 | 同一幂等键只能生成一笔订单；更改商品/数量/地址/优惠券不能复用同一键 |
| 测试付款 | 标注不扣款；订单待发货，可用积分仍不增加，待入账积分增加 |
| 商家登记发货 | 只有运营权限可提交；客户页面没有自行发货按钮；客户能看到手工登记的承运商/单号 |
| 收货 | 仅已发货订单可确认；按下单时的奖励快照入账；重复确认不重复发积分 |
| 积分兑券 | 扣减确定数量积分，生成带门槛和有效期的优惠券；积分不足或重复请求不重复扣分 |
| 下一单用券 | 满足门槛才可用；优惠后金额参与返积分计算；同券不能被两单同时占用 |
| 订单搜索 | 订单号/商品名可筛选，和状态取交集，清空后恢复订单列表 |
| 取消订单 | 只关闭待付款订单；库存与占用的购物券只恢复一次 |
| 实物积分兑换处理 | 客户看到兑换记录与商家处理说明，重复登记不再次扣分或库存，优惠券不能人工重复发放 |
| 收藏、签到及广告内部演示 | 收藏状态、签到防重复、领奖时长、冷却和日上限有效；不声称真实广告收益 |

## 商家运营

| 场景 | 验收结果 |
| --- | --- |
| 后台权限 | 无凭证/错误凭证无法读取管理数据或修改；凭证只在页面内存中使用 |
| 商品创建与编辑 | 字段校验、整数分价格、库存、积分价格、启用状态可保存；客户页反映上/下架 |
| 并发编辑 | 过期 version 返回冲突，不覆盖其他运营修改或订单占用造成的库存变化 |
| 积分规则 | 后台可配置有效整数返积分倍率；新订单按新规则，旧订单仍按原快照发放 |
| 订单列表 | 展示真实测试订单与状态；不把订单总额标成真实营收 |
| 发货登记 | 仅待发货订单可登记；同参数重复操作幂等，冲突信息不能静默覆盖 |
| 订单导出 | 需要管理员鉴权，最多1000笔，不含地址手机号；CSV公式防护及审计记录有效 |
| 广告配置 | 占位开关、激励演示开关生效；不伪装成真实 SDK 已接入 |
| 风控与审计 | 限制/解除奖励需运营权限；商品、规则、发货、售后等修改有审计记录 |

## 售后与退款账务

1. 客户对自己的适用订单提交售后原因，生成待审核申请，不立即把订单变为已退款。
2. 其他客户无法查看或处理该申请；客户不能调用管理员审批接口。
3. 运营驳回时填写说明；客户看到驳回状态和说明，订单账务不变。
4. 运营批准时库存、优惠券、积分和申请状态在同一事务内变更；重复批准不再次退款或补库存。
5. 购物返积分已消费而余额不足时，不得制造负余额或假装已退款：保留待审核并返回需要人工处理的明确错误。
6. 已完成订单的购物积分只按该订单快照回收，不使用审批时的新倍率。
7. 当前仅模拟业务账务，必须显示未退真实资金。真实支付退款网关与生产售后政策仍需接入及审查。

## 自动化命令

从源码项目目录执行：

```bash
npm run check
npm test
npm run test:e2e
npm run build
npm run build:weixin
npm run build:app
```

PowerShell 用 `npm.cmd` 替代 `npm`。浏览器测试使用独立测试数据库并启动自己的服务，运行前停止本项目占用的 3001/5173 服务；不要结束未知进程。测试固定管理员凭证只存在于测试配置，不可复制为真实环境密码。

浏览器验收命令依次为桌面、移动视口启动独立服务和数据库，避免跨套测试共用IP限流窗口；不会放宽应用限流。浏览器必须覆盖桌面和移动视口，检查控制台页面异常、横向溢出、商品图片、购物主线、商家操作反映到客户页、售后结果，以及匿名后台拒绝。资源编译成功不能代替真机验收。

## 账号和恢复补充验收

- 并发注册同一规范化用户名只产生一个账号；并发改密只能保留一组最终凭证。
- 改密等待密码派生期间退出，会话撤销后不得继续改密。
- 原匿名体验数据保留，不自动并入注册账号；页面说明匿名退出后不能凭用户名找回。
- 密码字段不进入本地存储、账务或普通审计明细；没有找回功能，不能显示虚假发送验证码结果。
- 恢复使用全新目标路径，完整性和外键校验通过才发布副本；拒绝损坏文件、已有目标及SQLite侧日志冲突。
- 恢复操作不修改 .env，不自动切换服务；包含中文及空格路径的CLI在构建环境验证，Windows真机单独记录。
