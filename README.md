# 曜集 AURORA

购物返积分商城，uni-app + Vue 3 四端共用界面，Fastify + SQLite 独立 API。明亮电商视觉、商品实拍示意图、价格和购物返积分同屏，移动端优先。原深色页面仅保留为运营管理入口。

**当前为可运行演示版，不是真实广告变现或可直接商用的交付版。** 没有复制参考站源码或图片。商品、积分、订单均为测试用途，不发货、不收款。

## 启动

需要 Node.js 24+、npm 11。

```bash
cd /workspace/gpt
npm ci
npm run start:local
```

启动脚本首次创建被 Git 忽略的 `.env`，生成随机运营访问凭证（不输出密钥），并启动 API 3001 与 H5 5173。Ctrl+C 停止脚本启动的进程。若已有 `.env`，不会覆盖；配置项参考 `.env.example`。运营后台入口在侧栏底部及个人中心，使用本机 `.env` 中的 `ADMIN_TOKEN`，不要在聊天或日志中粘贴。

也可在两个终端分别运行 `npm run dev:api` 和 `npm run dev`。服务默认绑定 127.0.0.1，API `/api/health` 应返回 `mode: demo`。不要将 Vite 开发服务直接暴露到公网。

## 验证与构建

```bash
npm run check
npm test
npm run test:e2e
npm run build
npm run build:weixin
npm run build:app
```

浏览器测试默认使用 `/usr/bin/chromium`；其他环境可设置 `CHROMIUM_PATH` 为已安装的 Chromium 路径，或调整 Playwright 配置使用其官方安装的浏览器。测试会独立启动服务，3001 与 5173 必须空闲；每次运行使用独立的 `.data/e2e-<进程号>.sqlite`，不会接触开发数据库。端到端测试里的固定运营凭证仅在该测试进程有效。

H5 输出 `dist/build/h5`，小程序输出 `dist/build/mp-weixin`，App 共用资源输出 `dist/build/app`。后者不是已签名 APK/IPA。设备构建前配置可访问的 `VITE_API_BASE` 并填入自己的平台 AppID。

## 已实现

商城搜索/分类/排序、商品详情、心愿单、购物车、数量修改、地址管理、购物券、结算、待付款订单、测试收银台、模拟发货、确认收货返积分、测试退款与积分回收、积分兑换、签到及广告内部演示、积分明细、运营管理与风控审计。

广告奖励每日最多五次，间隔至少 30 秒，完整演示后加 30 积分。签到日期按北京时间；普通日 20 分，每连续第七天 100 分。新账户初始 0 积分；旧版本已获得的余额保留。购物按优惠后金额每满 1 元返 1 积分，确认收货后入账，付款后显示待入账。取消订单释放库存与购物券，测试退款回收已发积分；余额不足则要求人工售后审核，不制造负积分。积分不支持买卖、提现、转让、抽奖或朋友圈分享奖励。

## 升级到购物返积分版本

从 GitHub 的 `codex/aurora-demo-delivery` 分支下载最新代码。先备份旧项目及本地 `.env`、`.data`；替换源码时保留这些本地文件，然后执行 `npm ci` 并重启前后端。数据库启动时会增量添加购物车、地址、购物订单及购物券表，不会删除旧积分和兑换记录。不要只替换前端，新增功能需要同步更新后端。

商品摄影来源和适用限制见 [素材说明](docs/ASSETS.md)。
